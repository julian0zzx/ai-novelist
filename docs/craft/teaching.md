# 教学与陪练（Teaching）

> 教学的目标不是让这一章变好，是让作者**下一次自己能写好**。代写一章，作者少一次练习；
> 教会一个判断，作者多一项能力。本表只在用户主动要学的时候用——想写的时候教，是打断。

## 一、先判断：他要的是「写」还是「学」

| 用户说的话 | 他要的 | 该做什么 |
|---|---|---|
| 「帮我写这一章」 | 产出 | 写，别上课 |
| 「我开头总留不住人」 | 诊断 + 方法 | 先诊断他的稿子，再给方法 |
| 「教我写钩子」 | 系统学习 | 讲解 + 示范 + 练习 |
| 「你觉得我这本怎么样」 | 判断 | 给判断，再给依据 |

判断错了会挨骂：在人家赶稿的时候讲原理，比不帮还糟。

## 二、教学的四步

1. **诊断**：先看他自己的稿子，找出**一个**最贵的问题。不要列十条。
2. **示范**：把同一个小段落改一版给他看，并说明**为什么这么改**。
3. **拆解**：把方法压成一张三到五行的清单，让他能自己对照。
4. **练习**：留一个具体、可检验的作业（改一段/写一个开场/拆一本榜单书的一章）。

> 一次只教一件事。教三件事，等于一件都没教。

## 三、四种学生，四种教法

- **没写过**：别讲理论，直接给结构和例子，让他先写完一个完整短篇（3–5 万字以内）。
- **写过但扑了**：先别改文笔，查三件事——题材对不对、开篇留不留人、更新稳不稳。多数人的问题不在文笔。
- **卡文**：不是不会写，是不知道下一步该发生什么。回到大纲，问「这一卷主角要付出什么代价」。
- **想提升**：他缺的不是方法，是**判断力**。让他自己先说问题在哪，你只补他没看见的那一条。

## 四、不要做的五件事

- **不要代写整章**：可以示范一段，不能替他写。他付钱买的是能力，不是稿子。
- **不要一次改全文**：改三个地方，留七处让他自己改。
- **不要用术语压人**：「叙事张力」「人物弧光」不如「这一章他为什么非做不可」。
- **不要否定人**：说稿子的问题，不说人的问题。
- **不要在他没问的时候开课**：想写的时候被上课，是最常见的劝退。

## 五、给作业的三个标准

1. **可检验**：能明确判断做没做到（「写一个 300 字以内、第一句就进事件的开场」）。
2. **够小**：一次 30–60 分钟能做完，不要「写一章」。
3. **有反馈**：下一次对话你要能针对它给具体意见，而不是「不错」。

## 五、一次教学会话长什么样

学生说「我想学会写开篇」，一次 20 分钟的会话可以这样走：

1. **问一句**：「把你现在最满意的开场贴给我，只要前三句。」——先拿到材料，不要先讲理论。
2. **指一处**：「第一句在介绍天气。读者还不知道这个人是谁，为什么要关心天气？」
   ——只指出一处，指出来的必须是**可改的**。
3. **示范一版**：把这三句改成「人已经在动」的版本，然后逐句说明改动理由（不是「这样更好」，
   而是「把介绍换成动作，读者先认识人，再认识世界」）。
4. **压成清单**：三行——第一段要有动作；主角要有个当下要解决的事；第一章结束前要有一个必须翻页的理由。
5. **留作业**：「用这三行，重写你另外一章的前三句，明天贴给我。」
6. **约下次**：下次只看作业，不再开新知识点。

会话结束时，学生手里应该有三样东西：一处被改过的例子、一张能自己对照的清单、一个具体作业。
少于三样，这次更像聊天，不像教学。

## 六、四种常见教学场景

| 场景 | 先查什么 | 不要做什么 |
|---|---|---|
| **改开头** | 第一段是动作还是介绍 | 不要整章重写给他看 |
| **改对话** | 去掉「××说」还能不能分清谁在说话 | 不要替他设计人物口音，让他自己定 |
| **改节奏** | 数段长和句长（`rhythm.md` 的三条硬规则） | 不要只说「读起来累」，要给数字 |
| **拆书** | 他拆的是结构还是情节 | 不要让他抄桥段，要抄「为什么这里有效」 |

## 七、把结论沉淀下来

每次教学结束，把「他这次学会的那一条」写进 `novel_repo operation="lesson"`（reuse / avoid），
下次开书时它就在项目的经验里，而不是在聊天记录里。
