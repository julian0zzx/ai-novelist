# 写作知识库（Craft Sheets）

> SOP 决定**该规划什么、按什么顺序规划、什么算欠账**；这里决定**写出来读起来像不像网文**。
> 每张表是一个可执行的自检清单，不是平台法规，也不是文学理论。

## 为什么需要这一层

`docs/sop.md` 能要求一章有钩子、有代价、有爽点，但它无法回答：

- 这个钩子具体该断在哪个动作上？
- 打脸四拍里少一拍，读者会先在哪一拍流失？
- 起点和番茄的开篇，第一段该差多少？
- 一句话里出现三个「不是……而是……」，该删哪一个？
- 这个赛道在卖什么体验，它的章级兑现和雷区在哪？
- 一章读着累，是句子的问题、段落的问题，还是整章没有起伏？
- 第 80 章和第 12 章对不上，先查哪一本账？

这些是**写作手感**，只能以知识库的形式给到写正文的模型。工具不评价文笔，知识库也不替作者做决定；
它把「凭感觉」变成「有清单可对照」。

## 怎么用

1. **只读当前问题相关的一张**。选题读 `genres.md` 与 `trends.md`；写第 1 章读 `hooks.md` 与 `platforms.md`；
   卡文读 `payoffs.md`；读着累读 `rhythm.md`；改稿读 `voice.md` 与 `continuity.md`；准备投稿读
   `submission.md`；出海读 `overseas.md`；写同人读 `fanfic.md`；交剧本读 `script.md`；要教人读 `teaching.md`。
   一次把所有表读完，等于没读。
2. **先对照，再动笔**。每张表末尾都有自检项；写完一章用对应表过一遍，比事后整章重写便宜。
3. **平台事实要复核**。本库不复制任何平台的规则原文，也不写死签约数字；凡是平台相关的内容都标了
   「经验值」。投稿前以**当期官方公告 / 作者后台**为准。
4. **冲突时以本书《写作风格》为准**。知识库给的是通用下限；作者已经确认过的声音、节奏、禁忌优先。

## 来源与边界

- 选题与分类参考了 [`tance-mang/chinese-webnovel-skills`](https://github.com/tance-mang/chinese-webnovel-skills)
  的公开目录（MIT）；本目录正文为原创撰写，未逐字复制其内容。
- 平台规则、签约门槛、敏感词范围会变，本库**故意不写死**这些数字，只给判断方法和经验区间。
- 本库不替代 `novel_review`：清单能指出「这里可能有问题」，判断「这段到底好不好」仍要读全文。
